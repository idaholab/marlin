# AnisotropicGBEnergy

!syntax description /TensorComputes/Solve/AnisotropicGBEnergy

`AnisotropicGBEnergy` evaluates a TorchScript model on grain-boundary normal vectors and stores both the resulting scalar grain-boundary energy and its derivative with respect to the incoming normal tensor in output buffers.

## Overview

The object expects `gb_gradient_buffer`, a vector-valued tensor buffer with trailing component dimension `3`, typically generated by [GradientVector.md]. The input is flattened to `(N, 3)`, normalized row-wise,

\begin{equation}
\hat{n} = \frac{\nabla \eta}{|\nabla \eta|}
\end{equation}

and passed to the TorchScript module to obtain the grain-boundary energy $\gamma(\hat{n})$, written to the `buffer` output. Autograd is used to additionally compute $d\gamma/d(\nabla \eta)$, written to the `dsigma_dn` output buffer with the same shape as `gb_gradient_buffer`.

Only points where $|\nabla \eta|$ clears a gradient-magnitude threshold are passed to the model. For a $\tanh$ interface profile of width `interface_width` ($W$), the threshold is

\begin{equation}
|\nabla \eta|_{\mathrm{thresh}} = \frac{2}{W \cosh^2(4)}
\end{equation}

which is negligible one interface width from the boundary. Outside this masked region, `dsigma_dn` is zero (there is no boundary to differentiate), while the energy buffer is filled with the largest energy value measured anywhere in the domain (or `1.0` if no interface point was found anywhere), to avoid introducing an artificial low-energy region in the bulk.

In two dimensions, [GradientVector.md] zero-pads the third (z) component of the gradient, so the model receives normals of the form $(\nabla_x \eta, \nabla_y \eta, 0)$ and must be trained (or otherwise tolerant of) this convention.
